# Local Explorer AI — Data directory

The data/ directory contains demo/simulated data, research experiments, and machine-learning training datasets for **Local Explorer AI**.

---

## 1. Simulated demo data

The legacy demo seed was generated by apps/api/scripts/seed_db.py.

### Legacy demo data described by the seed
- **10 simulated Saigon POIs:** Real-world coordinates in District 1 and central areas, flagged with verification_status = 'simulated'.
- **1 sample (synthetic) provider:** Used to test the Provider Portal and ownership permissions.
- **10 experience activities:** Crafts, Southern Vietnamese food, cultural heritage, urban nature, and relaxation.
- **30 days of slots:** 3 sessions per day (09:00, 11:30, 14:30), with open / full / tentative status.
- **Development accounts** (when APP_ENV=development):
  - Admin: admin@localexplorer.ai
  - Traveler: traveler@localexplorer.ai

> [!IMPORTANT]
> **Simulated-data boundary:** Simulated records must never be used for real bookings or payments through VNPay/MoMo. Real booking tests require records supplied by a real partner and approved by an administrator as verified, with current evidence.
>
> **Current status:** The legacy seeder is disabled because its previous behavior could infer missing facts and create fabricated evidence or slots. The list above documents the former demo fixture only; it is not a current operational inventory. Do not run it as a way to create real data.

~~~powershell
# From apps/api, after alembic upgrade head:
python -m scripts.seed_db
~~~

The old script was designed to be idempotent. Its command is documented for historical reference only; use the sourced-catalog workflow for current data.

## 5. Saigon and District 1 tourism places

| File | Description |
|---|---|
| data/sai_gon_places.json | JSON catalog of cultural, historical, food, and workshop places in Ho Chi Minh City, focused on District 1, District 3, and Cho Lon |
| Places/Sai_Gon_Places.xlsx | Original field-survey workbook |

**Fields intended for each place:** Name, kind, normalized address, GPS coordinates, opening hours, ticket price, indoor/outdoor, tags, historical/architectural description, field photos, and visitor ratings.

**Data workflow:**
~~~text
crawl_district1_places.py → download_district1_photos.py → attach_district1_photos_to_catalog.py
→ generate_full_places_data.py → apply_enriched_places.py
→ deep_check_excel.py / check_places_detail.py (integrity checks)
~~~

A file listed here is not necessarily present in the live catalog. The workbook's 177 rows currently require field-level source evidence before they can be published; see [place import staging](../docs/place-import-staging.md).

## 7. Place import staging

- **Migration:** 0010_place_import_staging — place_import_candidates table
- **API:** /api/admin/staging-places/*
- **Workflow:**
  1. Import XLSX/JSON/CSV into staging: python -m scripts.import_place_candidates --dry-run, then python -m scripts.import_place_candidates.
  2. Review in /admin (Staging Places tab): validate coordinates and detect fuzzy duplicates.
  3. After review and approval, promote the record into the main pois table.
